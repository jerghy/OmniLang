无限画布：三种空间组织方案

每个 .omni 文件是一个 tab，tab 内是一个无限画布——画布上怎么组织"视觉"和"逻辑"？

📍 A: 双锚点（你的方案一）

画布上有两个预设锚点——UI 视图区 + 逻辑节点区

画布空间示意
┌─────────────────┐     ┌─────────────────┐
│  🎨 UI 视图区    │     │  🔗 逻辑节点区   │
│                 │     │                 │
│  ┌───────────┐  │     │  [signal:count] │
│  │ Header     │  │     │      │          │
│  │ ┌───────┐ │  │     │  [computed:     │
│  │ │Counter│ │  │     │   doubled]      │
│  │ └───────┘ │  │     │      │          │
│  └───────────┘  │     │  [fn:inc]       │
│                 │     │                 │
└─────────────────┘     └─────────────────┘
    Ctrl+1 跳转              Ctrl+2 跳转

✅

  • 结构清晰
  • 快捷键直达

❌

  • 硬性分离违背"统一"理念
  • UI 和逻辑的连线跨越很远
  • 多组件时锚点不够

💬 B: UI 为主 + 浮层（你的方案二）

UI 视图是主画布，点击组件时相关节点浮出

选中 Counter 组件时
              [signal:count]──→[computed:doubled]
                     │
              [fn:inc]         [fn:dec]
                ╱ ╲               ╱
          ┌─────┐             ┌─────┐
          │Counter│           │ btn  │
          │     0 │           │  -   │
          └─────┘             └─────┘
          主画布（始终可见）    相关节点浮出

✅

  • 上下文关联强
  • 不选中时界面干净

❌

  • 全局视角缺失
  • 浮出位置不稳定
  • 无法同时看两个组件的逻辑

🎯 C: 缩放层级（推荐）

一个组件 = 一个空间区域。UI 在上，逻辑在下/周围。缩放控制可见粒度

三种缩放级别
100% 缩放（细看 UI）:
┌─────────────────────┐
│  Header              │
│  ┌─────────────────┐ │
│  │ Counter      0   │ │  ← 可以看到像素
│  │  [+]  [-]       │ │
│  └─────────────────┘ │
└─────────────────────┘

50% 缩放（看组件+逻辑）:
┌─────────────────────┐
│  [signal:count]      │
│     │    │            │
│  [comp] [fn:inc]     │  ← 逻辑节点浮现
│     │    │            │
│  ┌────Counter──────┐ │
│  │  count: 0       │ │
│  │  [+] [-]        │ │
│  └─────────────────┘ │
└─────────────────────┘

25% 缩放（俯瞰全项目）:
┌──────┐ ┌──────┐ ┌──────┐
│ App  │→│Header│→│Todo  │  ← 组件间关系
└──────┘ └──────┘ └──────┘

✅

  • 无硬性分离——UI和逻辑在同一空间
  • 空间记忆——Counter 的逻辑总在 UI 下方
  • 缩放自然控制可见粒度
  • Figma 用户零学习成本

⚠️

  • 需要精心设计缩放阈值
  • 节点位置自动布局算法很重要

🎯 推荐 C，理由很简单

需求 A 双锚点 B 浮层 C 缩放层级
UI 和逻辑统一空间 ❌ 分离 ⚠️ 半分离 ✅ 统一
连线可见性 ⚠️ 跨区连线长 ❌ 选中才显示 ✅ 始终可见
空间记忆 ⚠️ 两个区域 ❌ 浮层不稳定 ✅ 位置固定
多组件支持 ❌ 锚点不够 ✅ ✅ 自然扩展
学习成本 ✅ 简单 ✅ 直觉 ✅ Figma 用户熟悉

核心差异：A 是"两个房间"，B 是"东西藏起来"，C 是"一个房间，你决定站多远看"。
C 不需要切换模式、不需要锚点、不需要浮层——你只是改变观察距离。
