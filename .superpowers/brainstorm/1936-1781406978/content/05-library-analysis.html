🏆 推荐: 切换到 @xyflow/react (React Flow) v12

✅ 优势

  • 已安装 — 零额外依赖
  • React 原生 — 节点就是 React 组件，完美融入现有架构
  • v12 数据流内置 — useHandleConnections 直接对应 Data 端口
  • 自定义 Edge — SVG 组件画 Flow 线(白色三角) vs Data 线(彩色圆形)
  • 30k+ Stars — 最大社区，最佳文档
  • Zustand 兼容 — onNodesChange/onEdgesChange 可对接现有 store
  • 内置 Minimap, Controls — 比 Rete 插件生态更完善

⚠️ 代价

  • 需重写 FlowCanvas.tsx（846行 → 新文件）
  • 搜索面板需自建（但很简单：input + filter）
  • Rete.js 依赖可以逐步移除
  • 不使用 litegraph 的内置搜索（但它不兼容 React）

📐 React Flow v12 如何映射我们的架构

概念映射
React Flow          →  我们的 Visual Scripting
─────────────────────────────────────────────
Node (React组件)     →  Flow/Event/Action/Data 节点
Handle (端口)        →  Flow In/Out + Data In/Out 端口
Edge (连线)          →  Flow Edge (白色三角) / Data Edge (彩色圆形)
Node.data            →  ElementData.props + config
useNodesData()       →  数据流传播（Signal → Computed）
useHandleConnections() → 连接状态追踪
onConnect            →  addWire (复用现有 Zustand store)

🔀 执行引擎：自建 or 用库？

React Flow 只管渲染，不管执行。Flow 执行引擎需要自己实现（拓扑排序）

A

用 @xyflow/react + 自建 Flow Engine（推荐）

React Flow 负责画布渲染、拖拽、连线。自己写 ~200行 拓扑排序执行器。完全掌控执行逻辑，和现有 Zustand store 无缝集成。

B

保留 Rete.js + 自建 Flow Engine

继续用现有 Rete 画布。风险最小（不改渲染层），但 Rete 的 ClassicPreset 不如 React Flow 灵活。

C

引入 @comfyorg/litegraph

自带完整可视化脚本引擎（执行+搜索+蓝图节点）。但 Canvas2D 渲染，无法用 React 组件做节点 UI，和现有架构割裂大。
