🔄 7轮迭代计划

Phase 1: 基础架构（Round 1-3）
Round 1 — Flow Engine Core
• 重构 ElementData 增加 Flow/Data 端口分离
• 实现 Flow 执行引擎（拓扑排序执行）
• Rete.js 双色连线（白=flow, 彩=data）
Round 2 — 基础节点 + 节点面板
• Event: On Press, On Change
• Action: Set Variable, Run Code Block
• Data: Get Variable, Math (Add/Sub/Mul/Div)
• 可搜索的节点面板（替代 BlockPalette）
Round 3 — Flow Control + 完整 Data 节点
• Flow: Branch, Sequence, For Each
• Data: Compare, AND/OR/NOT, String ops
• 节点配置面板（点击节点显示可配置参数）
Phase 2: 完善与测试（Round 4-7）
Round 4 — 变量系统 + UI Property 节点
• 可视化变量管理（Variable Panel）
• Update UI Property 节点（改文字/颜色/大小）
• 变量拖拽到画布自动创建 Get/Set 节点
Round 5 — 代码块深集成
• Code Block 节点自动从参数生成输入端口
• 从返回值自动生成输出端口
• 在可视化图中无缝调用代码块
Round 6 — 代码生成
• 可视化图 → .omni 源码编译
• Visual Graph → React TSX 代码生成
• 双向同步（改源码 → 更新图 / 改图 → 更新源码）
Round 7 — 测试 + 真实应用验证
• 用 Smart Task Board 的全部交互逻辑重建
• Diff: 手写代码 vs 可视化图生成的代码
• 性能测试 + E2E 测试

🤔 问题：Code Block 节点集成的粒度

代码块如何在可视化图中使用？

A

黑盒节点（推荐）

Code Block 作为一个特殊的 Action 节点，有自动生成的输入端口（从 fn 参数）和输出端口（从返回值）。在可视化图中作为"执行步骤"使用。复杂逻辑全在代码块内部。

B

内联片段

允许在可视化节点内部嵌入小的代码片段（类似 UE Blueprint 的 "Custom Event" 节点中有个小代码编辑器）。粒度更细但更复杂。
