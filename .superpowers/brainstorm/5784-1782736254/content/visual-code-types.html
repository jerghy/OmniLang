可视化代码编辑：五大流派

从最结构化到最灵活 — 哪种适合 poiesis？

🧩 Block-Based（积木式）

Scratch / Blockly / Snap!

拖拽代码块拼接，语法天然正确，不会出错

✅ 适合

  • 教育/入门
  • 简单逻辑

❌ 不适合 poiesis

  • 表达能力太弱
  • 写复杂逻辑反而比手写慢
  • 生成代码质量差

🔗 Node Graph（节点图）

Unreal Blueprints / Houdini / Node-RED / Blender

节点 + 连线 = 数据流/控制流。业界最主流的可视编程范式

✅ 非常适合 poiesis

  • poiesis 已经有 @xyflow/react 节点图
  • 执行流+数据流双类型连线
  • 直观展示 signal → computed → view 的依赖链
  • 可以任意折叠/展开粒度

⚠️ 挑战

  • 复杂图会变"意大利面条"
  • 某些操作用代码写更简洁

📐 Structured Editing（结构化编辑）

JetBrains MPS / Hazel / Lamdu

直接操作 AST 而非文本。永远不会产生语法错误

✅ 优势

  • 零语法错误
  • 精确的代码生成

❌ 不适合 poiesis

  • 太重，需要完整语言工程
  • 学习成本高
  • 对 .omni 这种简洁语法，结构化编辑反而繁琐

📋 Form-Based（表单式）

Google Blockly 的属性面板 / Webflow 样式面板

通过填写表单、选择下拉、滑块来配置组件属性

✅ 适合

  • 属性编辑（style、signal初始值）
  • 组件配置

⚠️ 局限性

  • 只能编辑已有属性
  • 无法表达新逻辑

✏️ Text-with-Tooling（代码+工具增强）

Monaco Editor + LSP + Snippets + 实时预览

写文本代码，但有智能补全、实时诊断、内联预览

✅ 适合

  • 复杂算法/字符串处理
  • 批量重构
  • 已有代码片段粘贴

⚠️ 局限性

  • 纯文本，无结构约束
  • 可视化编辑器难以解析

🎯 对 poiesis 的建议：混合架构

poiesis 的"三合一"编辑模型
┌──────────────────────────────────────────────────┐
│              画布（WYSIWYG 预览）                  │
│  ┌─────┐  ┌─────┐  ┌──────────┐                │
│  │Header│  │Counter│  │TodoList │  ← 拖拽排列     │
│  └─────┘  └─────┘  └──────────┘                │
│                      │                           │
│            ┌─────────┴─────────┐                 │
│            │  Property Panel   │                 │
│            │  (Form-Based)     │  ← 属性表单      │
│            │  class: ___       │                 │
│            │  style: ___       │                 │
│            └───────────────────┘                 │
├──────────────────────────────────────────────────┤
│            节点图（逻辑编排）                       │
│                                                  │
│  [signal:count]──→[computed:doubled]──→[view:p] │
│        │                    │                    │
│        └──→[fn:inc]─────────┘                    │
│                                                  │
│  双击 fn 节点 → 打开 Monaco（代码编辑）            │
│  fn 节点可以折叠/展开内部实现                      │
├──────────────────────────────────────────────────┤
│           Monaco 编辑器（代码细节）                 │
│                                                  │
│  fn inc() {                                      │
│      count = count + step;  ← 复杂逻辑直接写代码  │
│  }                                               │
│                                                  │
│  这个 fn 的签名自动反映到节点图端口中               │
└──────────────────────────────────────────────────┘

核心理念

节点图是"骨架"，代码是"肌肉"。

高层架构、数据流依赖关系 → 节点图（直观、可追踪）

复杂算法、字符串处理等细节 → Monaco 代码块（灵活、高效）

布局、样式、属性配置 → 画布 + 属性面板（所见即所得）

三者共享同一个数据模型，不需要 annotation 记号——fn 节点的"端口签名"就是双向映射的锚点。
