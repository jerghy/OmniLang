行业参考：FlutterFlow vs Webflow

FlutterFlow 做法
🔷 没有"文件"概念 — 一切以项目为范围

📦 三级作用域：
App State🌍 全局
Page State📄 页面级
Component State🧩 组件级

🔄 导入：隐式自动
引用了什么就自动生成 import
开发者不用手动管理

🎯 组件参数 (Props)：
可视化地在属性面板定义
父组件传参，子组件接收
Webflow 做法
🔷 也没有"文件"概念 — 页面 + 组件

📦 作用域层级：
Site Variables🌍 全站
Page Code📄 页面级
Component Props🧩 组件级

🏠 Shadow DOM 隔离：
组件天然隔离，样式不泄漏

🎯 组件 Properties：
可视化定义 + 绑定
CSS 变量可穿透 Shadow DOM

核心洞察

FlutterFlow 和 Webflow 都没有"文件"这个概念。它们用「项目/页面/组件」三级作用域代替了文件系统。

但 OmniLang 保留了文件作为组织单位（类似 Rust/Go 的模块系统），这是故意的设计选择。

所以我们的问题是：如何把"文件"这个文本编辑器的概念，在可视化编辑器里做得直观？
