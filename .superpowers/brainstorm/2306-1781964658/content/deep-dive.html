板块 2：stagger 的精确语义

stagger(
  from { opacity: 0; y: 20 } to { opacity: 1; y: 0 } over: 300ms,
  each: 60ms,
  from: center
)

// 🔶 each: 60ms —— 是每个 item 比上一个延迟 60ms？ 还是所有 item 在 60ms 内均匀分布？
//    GSAP: stagger: 0.06 是间隔
//    Framer Motion: staggerChildren: 0.06 是间隔
//    → 建议：间隔

// 🔶 from: center —— 精确来说：
//    items[0] 延迟 0ms, items[N-1] 延迟 (N-1)*60ms？                    (from: start)
//    还是 items[N/2] 延迟 0ms，往两边各延迟 60ms？                       (from: center)
//    还是 items[N-1] 延迟 0ms, items[0] 延迟 (N-1)*60ms？               (from: end)
//    还是 items[0] 和 items[N-1] 都延迟 0ms，往中间递增？                (from: edges)

// 🔶 stagger 总时长计算：
//    3 个 item, each: 60ms, over: 300ms
//    最后一个 item 在 2*60=120ms 时开始，播 300ms，结束于 420ms
//    stagger 动画总时长 = (N-1)*each + over

板块 3：then / with / at 的运算优先级

// 🔶 A then B with C —— C 跟谁并行的？
// 理解 1：A then (B with C) → C 跟 B 并行，都在 A 结束后
// 理解 2：(A then B) with C → C 跟整个 A→B 并行
// → 建议：理解 1（with 优先级高于 then）

// 🔶 A then B at -0.1s then C —— C 什么时候开始？
// A ends, B starts at A.end - 0.1s = overlap with A
// C starts at B.start + B.duration（还是 B.end）？
// → 建议：at 偏移量相对于前一个 item 的 START 时间

// 🔶 A with B at +0.2s —— 并行分支能延迟吗？
// A 在 t=0 开始，B 在 t=0.2s 开始
// → 建议：可以
