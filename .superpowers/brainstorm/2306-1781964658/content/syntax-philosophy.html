动画语法设计：三种根本不同的哲学

不只是"放在哪里"——而是动画是什么的底层模型差异

哲学 A：CSS 启发式 — 熟悉的声明式
// 关键帧定义
@keyframes fadeIn {
  0%   { opacity: 0; transform: translateY(20px); }
  100% { opacity: 1; transform: translateY(0); }
}

// 元素上引用
<div animation: fadeIn 0.3s ease-out>
<div transition: opacity 0.2s, transform 0.3s>

// 入场
<div @enter="fadeIn" @leave="fadeOut">

// 状态过渡
<div transition:bind="activeStyle">

Pros

  • Web 开发者零学习成本
  • CSS 社区工具链
  • 关键帧语法成熟

Cons

  • 受 CSS 心智模型限制
  • 手势/物理需不同语法
  • 两个独立系统（transition + animation）
  • Flutter 映射不自然
哲学 B：Motion-First — 一切皆"运动"
// motion 是唯一原语
motion fadeIn {
  keyframes {
    0%   { opacity: 0; y: 20px }
    100% { opacity: 1; y: 0 }
  }
  over: 0.3s using: easeOut
}

// 物理弹簧也是 motion
motion springBounce {
  from { scale: 0.8 }
  to   { scale: 1 }
  over: 0.5s
  physics: spring(200, 15)
}

// 统一挂载语法
<div @motion:enter="fadeIn"
     @motion:exit="fadeOut"
     @motion:hover="scaleUp"
     @motion:drag="swipeCard"
     @motion:stagger="50ms">

Pros

  • 单一原语统一所有动画
  • 物理/关键帧/手势同一模型
  • Web + Flutter 都自然映射
  • 组合性好

Cons

  • 全新语法，需学习
  • 简单场景不如 CSS 简洁
  • 抽象层需要仔细设计
哲学 C：Signal-Animated — 动画即信号过渡
// 动画信号：值变化时自动插值
signal isOpen: bool = false;
@style cardStyle {
  when isOpen → { opacity: 1; scale: 1; y: 0 }
  default   → { opacity: 0; scale: 0.95; y: 20px }
  animate: 0.3s spring(200, 15);  // ← 动画作为信号的过渡规则
}

<div style="{cardStyle}" @click="{isOpen = !isOpen}">
  // isOpen 切换 → 样式自动插值过渡

// 列表编排
<div @for="item in items"
     style:animate="fadeSlideIn"
     style:animate-stagger="60ms">

Pros

  • 与 OmniView 信号模型深度统一
  • 消除"触发动画"的显式概念
  • 自然表达列表编排
  • 状态即动画源

Cons

  • 颠覆传统动画思维
  • 连续动画（spinner）不自然
  • 需要大量运行时支持
  • 调试困难
