动画能力缺口分析

逐项对照 GSAP / Framer Motion / Flutter / CSS —— 看我们漏了什么

🔴 可能遗漏的高优先级能力（影响日常使用）

1. 相对值：x: +=50 而非 x: 50

GSAP 支持 x: "+=50"，在当前值基础上偏移。没有这个的话，hover 动画不好写——比如 hover 时放大 0.05，你不知道当前 scale 是多少。

// 目前设计：必须知道绝对值
to { scale: 1.05 }   // 如果当前已经是 1.2 呢？

// 相对值：
to { scale: +=0.05 }  // 在当前值基础上加
to { x: -=20px }      // 向左移 20px

2. Transform Origin：缩放/旋转的原点

没有 transform-origin 的话，scale 从左上角缩放、rotate 绕左上角旋转——几乎所有 UI 动画都需要从中心变换。

@motion scaleUp {
  to { scale: 1.05 } over: 200ms
  origin: center        // top left | center | top right | 50% 50%
}

3. Hover 反向动画：离开时从当前位置平滑回去

目前 @hover={scaleUp} 离开时是直接触发 @leave 还是瞬间恢复？GSAP 的 hover 会自动 reverse。需要明确"反向播放"语义。

// hover 进入 → play forward
// hover 离开 → play reverse（从当前进度倒回去，不是从头播）
<button @hover={scaleUp}>   // 需要编译器知道: hover 离开时自动 reverse

4. 手势惯性/动量：松手后继续减速

拖拽松手后没有惯性会很僵硬。需要 momentum/velocity 支持。

<Card @drag-horizontal={swipeCard}
      @drag-momentum={true}
      @drag-velocity={$velocity}>  // 松手时的速度传给动画

5. Repeat Delay：循环之间停顿

loop: infinite 是连续循环。但常见场景"闪一下，停一秒，再闪一下"需要 repeat-delay。

@motion pulse {
  to { opacity: 0.5 } over: 200ms
  direction: alternate
  loop: infinite
  repeatDelay: 1s          // ← 每次循环后停 1 秒
}

6. 中断策略：动画冲突时怎么办？

如果 @enter 正在播放，此时元素被移除触发 @leave，怎么办？或者快速 hover/press 交替？

// 中断模式
@motion fadeIn {
  to { opacity: 1 } over: 300ms
  interrupt: stop           // stop（停住当前值）
                            // complete（立刻跳到终点）
                            // queue（排队等上一个播完）
}

7. 即时设置：不带动画的属性赋值

类似 GSAP 的 .set()——立刻把属性设到某个值，无过渡。有时候你需要先"归位"再播动画。

@motion init {
  set { opacity: 0; y: 50px }     // 瞬间归位（无动画）
  then to { opacity: 1; y: 0 } over: 400ms
}
