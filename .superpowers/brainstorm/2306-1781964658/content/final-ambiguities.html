剩余模糊点分析

🔴 核心问题：over: 的位置 = 模式判别器，但没写明

// ✅ 关键帧模式：over 在块级（所有 stop 之后）
@motion fade {
  from { opacity: 0 }
  to   { opacity: 1 }
  over: 300ms          // ← 块级 over，前面没有紧跟 {
}

// ✅ 时间线模式：over 在 item 级（紧跟 property block）
@motion entrance {
  to { opacity: 1 } over: 300ms       // ← item 级 over，紧跟 }
  then to { y: 0 } over: 200ms
}

// ❌ 歧义！没有这个规则，解析器无法区分：
to { opacity: 1 } over: 300ms
// 是：单 stop 关键帧 + 块级 over？
// 还是：单 item 时间线 + item 级 over？
// → 新规则：over: 紧跟在 property block 后面 → 时间线模式
//          over: 出现在所有 stop 之后（前面是 } 而不是 {）→ 关键帧模式

🔴 stagger() 的双重身份未明确

// stagger 可以出现在两个地方：
// ① 时间线 item（在 @motion 内部）
@motion list {
  stagger(fadeIn, each: 60ms)
}

// ② 内联表达式（在元素属性上）
<div @enter={stagger(fadeIn, each: 60ms)}>

// 问题：内联的 stagger 能嵌套吗？
<div @enter={stagger(stagger(fadeIn, each: 30ms), each: 100ms)}>
// → 需要明确：可以嵌套，语义是外层 stagger 包内层 stagger

🔴 states: 混合保留名 + 自定义名但缺 on: 的行为

// 场景：


// 没写 on: {signal}

// 当前 spec §20.1："custom state names require on: — otherwise compile error"
// 但是 idle 不需要 on:。这里是整体报错？还是只报 loading？
// → 明确：整体报错。只要 block 内出现任何自定义名，就必须配 on:
//   要么全是保留名（idle/hover/pressed），要么全自定义名 + on:

🟡 delay 同样有 item 级 vs 块级歧义

// 关键帧模式：delay 在块级（所有 stop 之后）
@motion fade {
  from { opacity: 0 } to { opacity: 1 }
  over: 300ms
  delay: 500ms       // ← 整个动画延迟 500ms
}

// 时间线模式：delay 在 item 级
@motion entrance {
  to { opacity: 1 } over: 300ms delay: 100ms    // ← 只这个 item 延迟
  then to { y: 0 } over: 200ms                  // 不延迟
}

🟡 时间线中无 then/with 的隐式连接符

// 时间线模式，两行之间没有 then：
@motion entrance {
  to { opacity: 1 } over: 300ms
  to { y: 0 } over: 200ms
}
// 等价于 then（默认 sequential），还是需要显式写 then？
// → 明确：隐式连接符 = then（sequential）。then 是可选的可读性关键字
