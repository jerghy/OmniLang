再次审查发现的缺口

1. 🔶 from 独立使用时的语义

// from { A } to { B } 很明确：A → B
// 但独立 from { A } 没有 to，终点是什么？

@motion reveal {
  from { opacity: 0; y: 20px }    // 起点是 0/20px，终点呢？
  over: 300ms
}

// 🔶 理解 A：GSAP 风格 — from {A} 意思是"从 A 动画到元素当前值"
//    元素当前 opacity: 1, y: 0 → 动画从 0→1, 20px→0

// 🔶 理解 B：必须显式 from/to
//    独立 from/to 都只是定义关键帧，缺少一端时报错

2. 🔶 关键帧块 vs 时间线 —— over 作用域

// 场景 A：多 stop 关键帧（共享 over + 独立 ease）
@motion bounce {
  0%   { y: 0 }     ease: easeOut
  100% { y: 0 }
  over: 600ms                      // 整个动画共享 600ms
}

// 场景 B：时间线（每项独立 over）
@motion entrance {
  fadeIn  over: 300ms
  slideUp over: 200ms start: ">"
}

// 🔶 什么时候 inside @motion 是场景 A，什么时候是场景 B？
//    规则建议：
//    - 有 0%/N% 百分比 = 关键帧模式（共享 over）
//    - 有 start 参数 = 时间线模式（独立 over）
//    - 同时有？→ 编译报错
//    - 都没有？纯 from/to 算关键帧模式（共享 over）

3. 🔶 set {} 的定位

// set 只在时间线中有意义（一瞬间赋值）
@motion init {
  set { opacity: 0; y: 50px }        // 瞬间
  then to { opacity: 1; y: 0 } over: 400ms
}

// 🔶 set 能单独作为 motion 吗？
@motion hide {
  set { opacity: 0 }                  // 有意义吗？就是一个 over: 0ms 的 to
}
// → 建议：set 只能出现在时间线中，不能单独定义

// 🔶 set 能内联在元素上吗？
<div @enter={set { opacity: 0 } then to { opacity: 1 } over: 300ms}>
// → 建议：可以

4. 🔶 动画清理 —— 元素卸载时

// 🔶 元素 remove 时，正在播的动画怎么办？
//     行为：立即 kill 动画，触发 onInterrupt 回调

// 🔶 @leave 动画播到一半，元素被强制移除？
//     行为：执行完 @leave 再移除（除非父级强制）

// 🔶 动画内存管理？
//     行为：动画完成后自动从全局 registry 移除
//           @loop infinite 的动画需要显式 kill

5. 🔶 Web 端 x/y/scale/rotate 的组合

// 我们设计的是独立属性：
to { x: 100px; y: 50px; scale: 1.5; rotate: 45deg }

// 但 Web 上它们都编译到同一个 CSS transform：
// transform: translateX(100px) translateY(50px) scale(1.5) rotate(45deg)

// 🔶 WAAPI 中 animate([{transform: "..."}, {transform: "..."}])
//    如果两条 transform 字符串分量不完全一致 → 插值失败
//    编译器必须保证 from 和 to 有完全相同的 transform 分量
//    缺的自动补默认值（x: 0, y: 0, scale: 1, rotate: 0deg）

6. 🔶 遗漏的属性：filter / backdrop-filter / boxShadow / clipPath

// filter 相关
blur: 0px→10px
brightness: 1→1.5
contrast: 1→1.3
saturate: 1→0

// 阴影
boxShadow: "0 0 0 rgba(0,0,0,0)"→"0 4px 12px rgba(0,0,0,0.15)"

// 裁剪
clipPath: "circle(0%)"→"circle(100%)"

// 🔶 这些要不要加入属性表？
//    建议：filter 系列加入（常见），boxShadow 加（Web only 警告），clipPath 加

7. 🔶 stagger + @for 的交互

// 列表数据变化时，stagger 怎么处理？

@for item in items key={item.id} {
  <Item @enter={stagger(fadeIn, each: 60ms)} />
}

// 🔶 新增 1 个 item（items.push(newItem)）：
//    A: 只动画新 item → 新 item 直接放最后，延迟 (N-1)*60ms 播
//    B: 全部重新 stagger → 所有 item 重新播（体验差）

// → 建议 A：key 匹配的旧 item 不动画，只动画新增和移除的

8. 🔶 参数互斥检查

// 编译时需要检查的参数冲突：
loop: infinite + fill: both       → 警告：fill 对无限循环无意义
loop: 1 + direction: alternate    → 明确：播 1 次来回？还是 1 个周期？
driven-by + loop                  → 报错：互斥
driven-by + direction             → 忽略 direction
ease + spring                     → 报错：只能选一个
