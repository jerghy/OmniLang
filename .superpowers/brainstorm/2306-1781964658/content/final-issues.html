Spec 深度审查：15 个剩余问题

从编译器角度逐行审查 790 行 spec 文档

问题 1：关键帧模式 vs 单条时间线的二义性

// 这个到底是关键帧模式还是时间线模式？
@motion fade {
  from { opacity: 0 } to { opacity: 1 } over: 300ms ease: easeOut
}
// 没有任何 timeline 特性（start/then/with/set/stagger/label/callback）
// → 默认判定为关键帧模式
// → 功能等价（单段关键帧 = 单条时间线），所以没问题
// 但有 timeline 特性时强制为时间线模式

→ 需要明确判定规则：含 then/with/start/set/IDENT/label/stagger/callback → 时间线；否则 → 关键帧

问题 2：with 分组的 then 语义不清

A over: 1s
with B over: 0.5s
then C over: 0.3s   // C 什么时候开始？

// 选项 A：after B.end (0.5s) — A 可能还在播
// 选项 B：after max(A.end, B.end) (1s) — with 形成一个 group

→ 建议选项 B：with 形成一个 group，then 在 group 结束后（最长 item 结束点）才开始。更符合直觉。

问题 4：纯回调 motion（无视觉 tween）

// 有些动画只需要回调——驱动逻辑而不改变视觉属性
@motion countUp {
  onUpdate: { displayValue = floor($progress * 100) }
  over: 1000ms
}
// 当前语法不允许：motion_body 必须有 to/from/timeline_item
// → 需要加 callback_body 模式，允许只有 over + 回调

问题 5：stagger 在时间线中，后续 item 何时开始？

fadeIn over: 300ms
then stagger(fadeOut, each: 50ms)    // 3 个 item: 总时长 300 + 2*50 = 400ms
then to { scale: 1 } over: 100ms     // 在 stagger 的最后一个 item 结束后开始

→ 明确：stagger 作为整体的"结束时间" = 最后一个 item 的结束时间 = (N-1)*each + motion.duration

问题 6：@states 只接受固定的三个名字

@states {
  idle:    ...    // ✅ 允许
  hover:   ...    // ✅ 允许
  pressed: ...    // ✅ 允许
  focused: ...    // ❌ 编译错误（不在允许列表中）
  dragging: ...   // ❌ 编译错误
}
// 只接受 idle / hover / pressed

问题 7：boxShadow / clipPath / d 参数的格式校验

// boxShadow: 两端必须同格式
// ✅ "0 0 0 rgba(0,0,0,0)" → "0 4px 12px rgba(0,0,0,0.15)"
// ❌ "0 0 0 red" → "0 4px 12px rgba(0,0,0,0.15)"（左侧无 rgba）

// clipPath: 两端必须同 shape 函数
// ✅ "circle(0%)" → "circle(100%)"
// ❌ "circle(0%)" → "polygon(0 0, 100% 0, 100% 100%)"

// d: 两端 path 段数必须一致（编译时）或形状近似（运行时兜底）
// ⚠️ 无法完全静态校验 → 默认编译通过，运行时如果失败则跳过该属性
