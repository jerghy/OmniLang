## Answer

**边界裁决细则与语言完整性原则定稿**（2026-08-09，用户四裁决全按推荐）。本模板为所有维度/批次裁决的共用判例。

### 1. 三判据执行判例（定稿）

| 判据 | 判定标准 | 证据来源 | 否决情形 |
|---|---|---|---|
| 跨目标一致表达 | 同一意图在三目标能否**行为对等**（floor 内，ADR-021）；「一致」≠ 逐字节相同——意图一致、实现差异由编译器选路（ADR-071） | 研究事实标准形态 + 编译器实现者判断 | 差异过大且无诚实降级路径（先例：懒加载 Flutter 缺位 → 否决进语言） |
| 编译器理解意图 | 编译器能否识别为**语义构造**（机制级 @drag / 功能设计级 @form/@load 先例）而非透传 | 实现锚点（parser/IR/semantic/codegen） | **透传不算理解**（40 透传事件先例：维持 DOM 语义 + Flutter 诊断兜底） |
| 真实语料需求 | **≥1 个真实语料位**（learn-omniview demo / 基准应用 / poiesis 用户场景） | 语料实证 | 零语料 → YAGNI 不立语法，记语言边界 + 触发条件（#83 motion-in-@for 先例） |

### 2. 裁决模板（定稿）

每能力项裁决输出固定四段：
```
能力项 | 跨目标一致（✓/✗ + 证据） | 编译器理解（✓/✗ + 证据） | 语料需求（✓/✗ + 语料位）
→ 结论：进语言 / 留生态 / 不支持
→ 设计方向（1-2 句，仅进语言项）
→ 触发条件（仅留生态/不支持项——语料或环境变化时重评）
```

### 3. 半实现信号处置原则（用户：标 v0 边界随批次补齐）

- 语言承诺**保持不动**（信号名/语法面），semantic-universe 状态列标「部分（v0 桩）」+ 每项带**补齐批次或触发条件**
- 与现有部分状态注册方式一致（域 8 formErrors/formValid/formSubmitting 已如此标注）；不动语言面、无破坏性变更
- 逐项处置清单随各批次裁决（如 form.submitting 随数据批次决定补齐或移除）

### 4. 留生态承接方式（用户：登记册标注 + 文档指引）

- **semantic-universe 状态值域扩展**：「留生态」成为合法状态值（现：支持/部分/未支持）——表示「语义集成员但裁决不进语言」
- 每条留生态项附：语言边界注记（含触发条件）+ **目标生态映射指引**（指向事实标准库，如分页→TanStack Query、路由→Vue Router）
- docs/omniview 相关文档同步指引（随各批次或 docs 批次）

### 5. 类型检查深化归置（用户：留 1F）

V6 字段类型匹配 + IR type_ann 缺陷 → **归 ROADMAP 1F 已知缺陷检查点**（既有归属不变）；能力基线聚焦词汇面，类型检查是编译器质量非能力词汇。fog 该项毕业关闭。
