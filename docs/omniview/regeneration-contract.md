# 再生成契约（Regeneration Contract）

> 设计层制度（v3 Phase 7）：生成代码与 `.omni` 源之间的关系契约。面向所有
> 会接触生成产物的人——人工开发者、LLM 编码代理、CI 门禁——定义「什么可以改、
> 什么不可以改、改错了会怎样」。

---

## 1. 核心契约：编辑 `.omni` 源，绝不编辑生成代码

**生成代码（React `.tsx`/`.module.css`、Flutter `.dart`、OmniView
`index.html`/`index.css`/`index.js` 等）是编译产物，不是源码。**

- 任何修复、调整、重构都必须落在 `.omni` 源文件里，然后**重新生成**。
- 手改生成代码的修复会在下一次重新生成时被**无提示覆盖**——这是契约的
  核心惩罚：不遵守契约的修改会静默消失。
- 代码审查标准：diff 中出现生成代码的手工修改（非本次生成输出的变化）即
  违反契约，应打回。

## 2. 生成代码是编译产物

| 产物 | 来源 |
|------|------|
| `build/<target>/` 下的所有文件 | `omnic build --target <target>` 从 `.omni` 全量重新生成 |
| React `.tsx` + `.module.css` | `component`/`store`/`design` 声明 → IR → React 后端 |
| Flutter `.dart` | 同源，Flutter 后端 |
| `__design/` 运行时文件 | `design` 块（token/class/variant/主题）专用命名隔离目录 |

产出结构由源文件路径推导（`src/components/Counter.omni` → `components/Counter.tsx`），
**不要移动/重命名生成文件**——重新生成时它们会回到推导位置。

## 3. 覆盖语义（Overwrite Semantics）

重新生成的行为声明：

- **全量覆盖**：`omnic build --target <target> -o <out>` 会覆盖 `<out>` 中
  同一编译器生成的所有文件（同名即覆盖，包括手工改动）。
- **不清理**：编译器只写它自己会生成的文件，不删除输出目录里的其他文件
  （残留文件不属于编译产物，由构建脚本/清理任务负责）。
- **不增量**：除非使用 `omnic watch`（增量重建），每次 `build` 都是全量
  重写——这是覆盖语义最简单的形式。
- **源文件不变则输出不变**：同一个 `.omni` 源 + 同一个编译器版本 → 字节
  一致的输出。生成输出是可复现的，diff 只应来自源或编译器变更。

## 4. 源追踪标记 `// [omni] <file>:<line>`

每个组件级生成文件（React `.tsx`、Flutter `.dart`）的头部携带源标记：

```tsx
// Generated by OmniLang — React target
// [omni] src/components/Counter.omni:3
```

- `<file>`：`.omni` 源文件路径（相对项目根）；`<line>`：该组件的声明行
  （1-based）。
- 数据来自 IR 的 `ComponentIR.source_file` / `source_span`（多文件编译时
  由 lowering 填充；手构 IR 的测试产物不携带标记）。
- 用途：
  1. **反向追踪**：拿到生成代码 → 直接定位 `.omni` 声明位置。
  2. **契约执行**：若一个生成文件没有标记（或标记指向不存在的位置），
     说明它是手工产物或来自未知源——不满足契约。
  3. **LLM 协作**：LLM 看到生成代码时先读标记回源，避免在产物上推理。

## 5. 诊断契约：编译器是错误事实来源

- 编译错误/警告由编译器以结构化诊断（`Diagnostic`：code/message/line/col/
  suggestion）给出；**不要为了绕过诊断而修改生成代码**。
- 诊断给出的位置与建议（`suggestion` 字段）是权威的：修复 `.omni` 源 +
  重新生成，而不是在生成产物上打补丁。
- 生成代码中出现的运行时错误，同样先回源排查（见 §4 标记），源修复后重新
  生成验证。

## 6. 工作流

```bash
omnic build --target react -o build/react-test-app   # 修改 .omni 后重新生成
omnic watch                                          # 源变更自动重建
omnic analyse <file>                                 # 不生成代码，只做静态分析
```

CI 侧：`verify-react`（tsc + eslint）与 Flutter 门禁均对**重新生成后的产物**
运行——提交前先重新生成，确保门禁验证的就是将发布的输出。

## 7. LLM 协作语义

- 语料定位：LLM 编码代理的常见错误模式（错误事件名/方法名、删除语法、
  缺 `view{}`、错误闭包形式、组件完整性）由
  `omnilang/tests/llm_error_corpus.rs` 在 CI 上钉死——诊断存在、位置精确、
  提示可行动。
- 生成代码中的 `// [omni]` 标记是给 LLM 的地图：永远从标记回源编辑。
- 覆盖语义是给 LLM 的纪律：在生成代码上「修复」是无效劳动——重新生成即
  抹除。
