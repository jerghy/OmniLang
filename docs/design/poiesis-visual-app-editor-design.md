## 1. 总纲：极佳体验 = 想法 → 落地的关卡全部消失

**产品本质**：OmniLang 是"意图语言"（用户表达"想做什么"，不写平台形状，ADR-054），而 Poiesis 现在是"意图语言的**文本**编辑器"——语言是意图级的，编辑却是文本级的。**这个错位就是"带编译预览的文本编辑器"的本质**。全部设计任务 = 消除错位：让语义全集里每一条用户可表达的意图，都有一个一等公民的可视化表面。

**一句话**：用户面对的唯一对象是**他的应用**；编辑器的一切结构都是应用结构的投影；让想法到落地的每一个关卡都消失。

不会写代码的人（目标用户 = 半专业 B + 非技术 C，视觉优先）做一个应用，卡住他的只有四件事：

| 关卡 | 拆法 |
|---|---|
| **不会用** | 没有空白的开始：一句话孕育骨架；组件库 = learn-omniview 42 个活 demo |
| **接不上数据** | 内容长在界面上，"接数据"这个动作不存在（§6） |
| **怕弄坏** | 时间树分支 = 有保险的冒险；错误只长在发生处（§9） |
| **想不出来怎么做** | 语言即界面：编辑器结构 = 语言结构，UI 上的每个词都是语言里的词（§11） |

**"舒服"的四条判据**：
1. 不离开上下文——编辑与所见同一视口
2. 每个概念只有一张脸——一个语义不在多处编辑
3. 错误在发生处显示——语义验证三态直接渲染在对象上
4. 概念与语义 1:1——用户永远看不到 div/CSS/DOM，只看到组件/属性/token/意图

## 2. 全景：一对象 · 四透镜 · 一车间 · 一树 · 四标签页

```
                 ┌─────────────────────────────┐
                 │      你的应用（活的对象）       │
                 │  打开 Poiesis = 打开应用本身     │
                 └─────────────────────────────┘
   建造透镜(长什么样)  因果透镜(怎么反应)  内容透镜(有什么)  结构透镜(由什么组成)
   应用即编辑器        行为是对象的属性      内容活在界面上      应用的一生
   ──────────────────────────────────────────────────────────────
   车间（数据处理）= 逻辑的居民：数据页（客厅）↔ 函数节点（书房）
   时间树（元层）   = 撤销 / 版本 / 灵感存档 / 发布 / 协作
```

- **一个对象**：你的应用，活的。没有"编辑器外壳"、没有设计/运行模式——打开就是应用本身。
- **四透镜**：看同一个对象的四种尺度。**缩放是导航，不是切换；预览是默认，不是功能。**
- **一车间**：数据处理（§8）。
- **一树**：时间（§9），跨透镜的元层。
- **四标签页（信息架构，08-09 拍板）**：主应用 / 组件开发 / 样式开发 / 数据处理开发；家族树 = 元层按钮，跨标签可用；调试窗口 = 独立真窗口（§3）。
- **演进记录**：本设计的直接前身是"四张脸"（设计画布 / 数据面板 / 逻辑画布 / 内嵌预览），被用户否决（模式化框架），由四透镜取代。四张脸中的有效元素已并入：内嵌预览 → 呼吸三态与调试窗口、事件→行为接线 → 因果透镜、@form/@load 绿地 → 内容透镜。

## 3. 呼吸三态：睡 / 醒 / 调试窗口（应用的两个呼吸）

> 08-09 定案。问题起点：**"应用即编辑器"只符合设计阶段，没加入逻辑**——点按钮会加载数据，这个"它在跑"的界面怎么来？

**三态全貌**：

| 表面 | 状态 | 能做什么 | 对应语言层 |
|---|---|---|---|
| **设计窗口** | **睡**（默认） | 只能设计界面 + 样式（含测试数据集 / 幽灵元素 / 呼吸灯） | 视图层 |
| **设计窗口** | **醒** | 接数据（桥/点名）、接事件（行为卡）、让界面活起来 | 逻辑接线层 |
| **调试窗口**（独立真窗口） | —（运行） | 应用真的在跑：数据流动、三态在演、状态条、试机台、单步断点 | 运行时 |

- **睡（默认）**：应用是一张画。摸到的就能改（直接操纵），但"活"的部分——数据流动、逻辑运行——不演。
- **醒**：应用是"会思考的界面"。数据在流、前提标签点亮、可以接数据接事件。**可局部醒**：整页醒，或只醒选中组件（选中一个按钮 → 点醒 → 只接它的数据和事件，其余保持睡）。
- **呼吸点**：设计窗口角落的一个小脉搏。点它 → 应用醒（编辑器具隐去）；再点 → 睡（家具回来）。**醒 = 家具消失，睡 = 家具回来**——"呼吸"是窗口的物理行为，用户只学一个动作。
- **调试窗口**：从"跑起来"请出的**访客**（独立 OS 窗口），应用真的在跑——三态在演、状态条、三态开关、试机台、单步断点。用完关掉，设计窗口永远在原地；多屏用户把访客拖到第二块屏。
- **接力关系**：睡 →（点呼吸点）→ 醒（接数据/接事件）→（点"跑起来"）→ 调试窗口（真的在跑）→ 关掉回到设计窗口。
- **呼吸范围修正（关键）**：睡/醒 **不是互斥的两个模式，是数据流动的开关**——正交于样式编辑。**醒着也能改样式，睡着也能接数据（接了先不流）**。"开发数据的时候无法改它的样式"这个矛盾不存在。
- 语言契约：睡 = 视图层；醒 = 逻辑接线层；调试窗口 = 运行时。三态是语言三层结构的编辑器投影，不发明新概念。
- 与已拍板工具的关系：状态条 / 三态开关 / 试机台全部自然住进调试窗口，不另造机制；状态预览开关 = 应用"醒"的临时一瞬。

## 4. 建造透镜：长什么样（应用即编辑器）

- **无模式、直接操纵**：悬停浮现操作柄；选中浮现语境面板；拖动即改布局；双击文字即改文案；拖边角即改尺寸。摸到的就是最终用户摸到的。
- **语境面板替代固定侧栏**：选中什么浮现什么；面板结构 = 语言结构（语言加新属性，面板自动多一节）。什么都不选 → 应用的面板。
- **组件库是活的例子**：learn-omniview 的 demo 就是组件库，拖进来就能用、能改、能看它怎么做的。模板不是空壳，是活的生物。
- **空状态即引导**：空应用不是空白画布，是一句"从左边拖一个按钮，你的应用就出生了"。
- **文字即数据，数据即文字**：输入框打字 = 设默认值；绑了数据后打字 = 直接预览数据流变化。
- **设备框抽象**：运行形态不约束设计（拍板 #4），画布预留手机/桌面设备框切换；预览不是独立窗口——**应用本身就是预览**。
- **代码是应用的 DNA**：它存在、可导出、可 diff、可版本控制（保住产出质量的底线），但用户不需要读它——就像人不需要读自己的基因。Monaco 降级为隐藏的专家出口：默认不可见，代码查看 / 专家模式再打开。

### 有前提的元素（@if / @for 的显形）

> 08-09 定案。条件渲染与列表渲染不是两个问题，是一个问题的两种形态——**"一个元素的存在有前提"**。统一解法 = 在睡态把"前提"显形：有前提的元素永远可见、可改，但被标上"前提标签"；条件/数据源在睡态可留空（设计先完成），醒态再接。**先设计、后接逻辑**——与"内容先呈现后来源"同一心智。

- **@if = 幽灵元素**：条件为真的内容正常摆着（它永远是它）；条件本身 = 一个"幽灵"——当条件为假时，元素半透明显示，头顶悬浮小标签："仅当 [登录后] 显示"。幽灵可选中、可移动、可改（改的是内容）；点标签 → 打开条件卡 → 醒态接上真实条件。**@if 不是一个抽象概念，是一个"有前提的演员"。**
- **@for = 一显多隐**：列表只显示一个代表性条目（第一行就是代表）；其余条目 = 若隐若现的幽灵行（能看见有多个，但淡出在背景里）；头部小标签："这个列表由 [报名] 驱动，共 3 行"。点标签 → 换内容源（点名数据页）→ 醒态看多行真实数据流动。**你设计的是"一个条目的样子"，系统负责"乘以 N"。**

### 层级感：呼吸灯（定稿）与骨架视图（待深化）

> 08-09 定案：**不设元素树**（元素树 = 把 div/DOM/嵌套关系暴露给用户 = 违反语言契约；B/C 用户看到一棵满是 div 的树只会更乱）。层级感由三样东西给：应用树侧栏（应用/页面/组件/条目/数据页/设计语言——用户熟悉的东西）+ 呼吸灯 + 页面骨架视图。**层级感的目标不是"看清 DOM"，是"想得快"**——骨架清晰 → 架构想得清 → 想法落地快。

- **呼吸灯（定稿）**：悬停任何元素，它的**父级链条**（爷爷→爸爸→自己）在画布上亮起呼吸光带——不是静态边框，是**可点的光带**：
  - 悬停 → 光带一路亮到祖先，"我在哪"永远可见
  - 点光带上任何一环 → **直接选中那一层**，改它、挪它、重排它——**层级就是操作对象本身**，不是"看"的
  - 光带是呼吸的（微光脉动），不是静态框——**"层级是活的"**，跟"应用是活的"同一个心跳
  - B/C 用户不用学"父容器/子元素"这些词——他们只看到"点一下爷爷就能改爷爷"，层级感从"认知负担"变成"操作便利"
- **页面骨架视图（乐高拆解台，待深化）**：骨架 = 可拆装的积木。打开骨架视图，页面变成区块积木图（头部区/表单区/统计区/页脚区…）：拖 = 重排区块顺序；跨页拖 = 移动区块（结构手术）；点积木 ↔ 画布双向高亮。**架构动作（重组/搬迁/合并）全部在积木图上直接做**——接上结构透镜"生长（地图+手术）"那幕：骨架视图 = 单页级手术台，结构地图 = 应用级手术台，两个尺度同一双手。08-09 用户裁定："还差点意思，这个后面设计"——记入待定表，不阻塞定稿。

### 组件：用户主动创建、用户管（08-10 定案 · 推翻 08-09 #21）

> 08-10 用户裁定：放弃"系统发现重复 → 提示合并 → 长成组件"（拍板 #21）——"系统发现然后合并过后，其实并不能帮助用户多少"。组件是用户**自己开发、自己创建**的对象；编辑器的职责 = 把真实开发过程变得平稳顺利，而不是替用户做抽象决定。产品用词：**组件**（复用）与**积木**（层级感）——"用户理解'零件'，不理解'组件'"的说法作废，组件/积木直接进入用户语汇。

- **两种创建方式（用户主动）**：① 设计页面上**多选几个元素 → "做成组件"**——边界用户自己划，选了什么，组件就是什么；② **直接创建空白组件**（先有盒子再装内容）。系统自动发现/合并彻底关闭。
- **组件的用处有二**：
  1. **复用**（含变体）：同一个东西，多处用、多种形；改它，处处变。变体 = 复用的子集——同一组件预制多种面孔（报名卡 / 详情卡），各处用的时候微调。
  2. **积木**（层级感）：组件在应用树里占一位、装一堆东西，应用有了层级；可拆装、可嵌套、可整体搬用——**"把它当成 page"**。
- **积木的显示与编辑（用户裁定"不搞复杂"）**：积木内容在画布上**平铺显示、无特殊边界**，跟普通元素没有两样；层级感由**应用树（积木占一位、可展开、可嵌套）+ 呼吸灯**承载——"这是一块积木"在树里表达，不在画布上画框。要设计积木内部 → **单独拎出来**：画布切换进积木内部（像切换进一个页面），顶部面包屑（报名应用 / 报名页 / 报名卡）点按返回。积木可以**单独醒**：选中积木点醒 → 只在积木内部接数据接事件（与部分唤醒同一机制，§15.4）。
- **复用组件与积木的分工**：两者创建方式相同（多选做成 / 空白创建），管理方式不同——复用组件 = 独立解剖室式设计（属性/变体/数据挂钩，处处变）；积木 = 就在应用里显示、拎出来编辑。复用组件的解剖室细节（属性怎么定、画布显示形态、变体管理）**待深化**（§13 待定 #13）。

## 5. 因果透镜：怎么反应（行为是对象的属性，不是逻辑图）

> 用户认可原话："因果透镜：行为是对象的属性，不是逻辑图，将界面的逻辑可视化，让用户编写应用的逻辑的时候，会更加思维清晰"

- **行为卡**：逻辑附着在对象身上。选中按钮 → 语境面板里"它会做什么"一节，一个按钮的完整行为清单，像说明书。添加行为 = 自然语言规则卡：`当 [点击] → [把] [计数器] [加 1]`。填卡像填表，不像是画图。
- **时间流视图**：复杂对象的行为按发生顺序排开（"打开页面时 → 加载数据 → 显示骨架屏…"）——CodeFlow 的升华形态：不是流程图，是行为的时间线。
- **数据也是对象，也有行为**："当 [流水数据] 变化 → [自动] [重算统计]"。
- **状态条**：应用所有数据像仪表盘常驻一处（住进调试窗口）；B/C 用户调试 = 拨动开关、改数值、看应用当场变。加载/错误/空态不是"要写代码处理的事"，而是三格填空："加载时显示 [骨架] / 出错时显示 [提示+重试] / 有数据时显示 [列表]"。
- **拖动类行为也是填空**："这个卡片 [可以拖动]，方向 [水平]，最远 [屏幕一半]，松手 [回弹]"——@drag 约束变成填空，不是参数。
- **跨组件事件链**：子组件事件 → 父组件事件 → store action 的可视化接线（现状缺口：EventsSection 能声明 event，但画布无连线建立链路）。导航"点这个按钮去那页"是结构层的画线，组件间行为链是这里的画线。
- **与呼吸三态的关系**：行为卡的接入发生在**醒**态——睡态设计界面，醒态接数据接事件（§3）。

### 就地 vs 独立（逻辑的两档，一个连续的心智）

> 用户反问："我点一个 数字+1 的按钮，它就是数字加 1，难道也要过一遍车间吗？它明明就是个闭包就能实现的"

| | 就地（行为卡） | 独立（函数节点/数据页） |
|---|---|---|
| 心智 | "这个按钮点一下加 1" | "报名按项目分组的统计" |
| 驻留 | 对象的因果透镜里 | 应用树里（命名后成为居民） |
| 规模 | 一步逻辑 | 任意长度 |
| 复用 | 无 | 多处点名 / 参数口 |
| 语言 | action / computed | fn / getter / @load |

- **用户不选档，系统按需给档**：第一个"数字+1"就地住行为卡；同一逻辑第二处出现 → 系统问"要变成公共的吗？"——抽象/重构的收益自动到手，用户永远不学这两个词。
- 地界：一步就地；两步以上或第二处要用 → 就地自动"升级邀请"。
- 语言契约检查：就地↔独立的界 = 语言 action↔fn 的界。

## 6. 内容透镜：有什么（数据 = 内容 = 条目）

> 迭代结论（用户方向）：回到"开发时数据到底怎么被用"的根本——想法里有内容，内容要出现在界面上、要被收集和更新。**解法是让"接数据"这个动作本身消失。**

- **内容长在界面上**：没有"数据模型"这个词。往页面放一个列表 → 列表出生了：列 = 字段、行 = 内容，当场可改。改列、加行、删行 = 定义内容。
- **先呈现，后来源**：内容先以样例活着；来源是最后的问题、可选项（人话三选）：**我自己维护**（界面上直接改）/ **别人提交**（配一个收集入口）/ **从别处接**（给一个来源）。换来源不碰设计。
- **一处内容，多张面孔**：同一内容在首页是列表、详情页是卡片、统计页是图表——面孔各管样式，内容一处变、处处变。点一下内容 → "我出现在这 3 个地方"，点一下跳过去。**"数据多了脑子不乱"的答案：没有"管理所有数据"的地方，内容按"是什么"分散在应用里。**
- **呈现方式是一等公民**：列表旁边就是菜单："换个样子看：卡片 / 表格 / 柱状图 / 折线图 / 占比图"。筛选/排序/分组/统计也是菜单，是人的话（"只看上个月的""按分类分组""最底下显示总计"）。**数组能力变成菜单选项，用户永远不碰"处理数据"这个动作。**
- **收集 = 表单，表单 = 内容的口**：表单设计器 = 把字段拖进表单，收集入口就长好了；每个字段下面挂**规则卡**——"必填" / "范围 1-100" / "格式：邮箱"，规则是人的语言不是正则，错误文案也是填空。发布后内容还会长——应用是活的。
- **自己会算的字段**："剩余天数 = 截止日期 - 今天"。
- **内容不存在时的引导**：从用户摆好的呈现草稿问"这个内容还不存在，要创建它吗？"——内容从草稿里长出来。全程没有一个动作叫"接数据"。
- **否决记录**：外部数据"拖 Excel/CSV 导入"方案被用户否决（"为什么拖拽 Excel 表格？这些我觉得不是很妙"）——外部接入的具体形态待定。

### 测试数据集 = 界面的活体模特（08-09 定案）

> 用户裁定："既然界面是数据的可视化呈现，那在开发过程中可以准备一些测试数据集，这样在开发界面时能更好地进行。"

界面是数据的可视化 → 开发时需要一个"身体"来穿。测试数据集 = 界面的**活体模特**：设计列表，模特替你穿好这身行头（3 行报名记录），改样式立刻看到效果；接上真实来源后，模特退场，真实数据上台。它也彻底化解"开发数据时无法改样式"——醒态流的是测试数据：**它是活的（能看流动），也是你的（能在界面上直接改行、改值）**。改数据 = 改模特的身材，改样式 = 换衣服，同时进行。

| # | 要点 | 说明 |
|---|---|---|
| 1 | **出生自带** | 每个内容出生时就配好一套测试样例——不是空壳，是系统按应用的一句话（"记账应用"）生成的**合理域内数据**（3~5 行，字段类型正确） |
| 2 | **界面可改** | 样例直接在界面上改（改行/加行/删行）——内容长在界面上，测试数据也长在界面上 |
| 3 | **可换数据集** | 样例不是一套：**常规 / 空（看空态）/ 超大（看滚动）/ 特殊值（超长文本、极大数字——看你的设计扛不扛得住）**——把"特殊渲染情况"从"没想到"变成"一键换装" |
| 4 | **与试机台共用** | 同一套样例既是界面设计的身，也是试机台（已拍板）的质检输入——一个数据集，两种用途，不搞两套 |
| 5 | **发布隔离（不留隐患）** | 测试数据**永远不发布**。发布时系统明确清单："这个列表发布后显示：真实数据（3 条）"——测试数据带视觉标记（幽灵标签同款："这是测试数据"），边界清晰，绝不混入生产（执行拍板 #13：B/C 用户最怕"填了假数据的表单发给客户"） |

**迭代教训**（防止未来重蹈，判据优先级与样式板块同等）：
- 第一版"数据卡（从哪来 / 用在哪）"被否——用户："回归到最根本的上面，在开发应用的过程中，数据或是内容到底是怎么在这开发过程中去使用的？""不能因为数据多了，用户的脑子就变乱了。或者是用户本来有一个想法需要用到数据，但是就卡在使用数据这个关卡上面。"——**数据层一切设计的判据 = "使用数据的关卡是否消失"**。
- 第二版（条目三合一 + Excel 导入）也被否；收敛 = 第三版（本节：内容长在界面上、先呈现后来源）+ 08-09 测试数据集补全。

### 身份 = 普通逻辑（08-11 定案 · G4 关闭）

"我的报名 / 我的收藏 / 我的活动"这类"我的XX"——拆到底**都是普通逻辑**，不是新概念：
- "我的报名"页 = 列表 + 筛选"只看 [报名人] = [我]"——筛选菜单/行为卡本来就写"只看 [字段] = [值]"，"我"就是那个值
- "取消按钮只在我的报名上显示" = 幽灵元素，前提 = "报名人 = 我"（§4）
- "我"在开发时 = **测试数据集的测试身份**（活体模特拨到张三，"我的"就是张三的；拨到李四就是李四的——与换数据集同一机制）；发布后"我" = 登录系统 = 运行世界（待定 #4 记案，不在设计范围）
- **教训**：看似特殊的需求（身份/我的），先拆成已有机制再定"设计空白"——"我的XX"拆完没有空白；若有表达不出来的，那是行为卡动词库（G3，待定 #15）的表达力问题，不是新设计。

## 7. 结构透镜：由什么组成（应用的一生）

> 迭代结论（用户方向）：不只 0→1 的架构设计，还要覆盖**后续维护与重构**——"让用户有一个想法就能立即去用应用实现，且落地过程体验极佳"。

**架构 = 应用的结构，且结构是可以动手术的。**

**迭代教训**：第一版"放大透镜 = 远看地图（鸟瞰 / 缩放导航）"被否——用户："放大透镜好像设计的不是很妙"。架构是用户最初列的三大能力之一（界面 / 逻辑 / 架构），**必须是"能设计的层"，不是查看器**——所以结构层的一切都是"手术"：出生 / 生长 / 演化 / 健康，每幕都可动手、都有保险。四幕：

**第一幕 · 出生**（0→1）：新建应用不是"新建项目"，是**孕育**——一句话（"我想做一个记账应用"）→ 骨架出生（几个页面、每种页面放什么、有哪些条目、页面怎么走）。骨架来自**器官库**：learn-omniview demo 拆解成的"应用器官"（列表页/表单页/详情页/仪表盘/设置页），拖进来就能用能改；也可以空白出生，骨架自己长。

**第二幕 · 生长**（地图 + 手术）：应用长大后，结构层 = 一张活地图——页面像岛屿，导航是岛间航线。地图上做的都是**结构手术**：增删页面、拖拽重排、**给按钮配"点它去哪"**（换页 = 发射端/接收端模型，§16——08-11 推翻"导航画线"，不画线、不建页面总览视图）、把重复卡片**合并成共享组件**（系统主动发现："这个卡片在 3 处重复，合并成一个？改一处三处都变"）、全局改主题色。**与层级工具的分工**：骨架视图（乐高拆解台，待深化）= 单页级手术台；结构地图 = 应用级手术台——两个尺度，同一双手。

**第三幕 · 演化**（维护与重构 = 想法落地零恐惧）：重构最怕的不是干活，是怕弄坏。解法：**大动干戈默认发生在分支世界里**——
- 想法（"把整个应用改成深色电影感""三个页面合并成工作台"）→ **开一个分支**，主干安然无恙
- 分支里随便折腾，怎么都弄不坏
- 折腾完，主世界和分支世界**并排对照** → 满意**嫁接**回主干 / 不满意放弃
- 分支还能**单向偷师**：把分支里单独一个页面拖回主干
- 用户认可原话："时间之树…能跟我前面说的架构相结合。用户有什么想法想快速落地，直接开一个分支就可以把想法落地"

**第四幕 · 健康**（体检，维护的雷达）：跨页面视角的语义验证——"这个卡片在 3 处重复""这个表单还没接内容""这个页面的错误态没设计"。**每条提示 = 一个可执行的动作**（合并它 / 接内容 / 补错误态），点一下就是一次小手术。

四幕是同一个"应用"对象在不同生命阶段的样子，不是四个模式。**结构层的本质：应用整体是可以直接动手的对象，且永远有保险。**

### 多应用的家（果园，记案待展开）

打开 Poiesis = 走进**果园**：每棵树 = 一个应用（微缩树形——主干 + 果实 = 发布版本 + 分叉 = 平行世界），点进树干 = 走进编辑器（回到上次的地方）；空果园 = 一句"种下你的第一个应用"。树住在果园里 = 云上持久（产品承诺，技术后定）——"怕丢"的恐惧在门里就消解；复制/分享别人的应用（远期协作）是果园里的动作：折一枝回去种。08-09 用户裁定"这个涉及的有点多了，回到根本"——**记入待定表，不展开**。

## 8. 车间：数据处理（逻辑的一个家，两级）

> 用户最终裁定："旧地和那个什么车间是一起的，就是上下级关系。车间相当于是一个函数，旧地就相当于是个可视化的数据处理界面…函数是这个可视化数据编辑器的数据处理节点"
> 界面/处理分离在语言层早已成立（编译目标 = UI 三件套 + 纯逻辑四目标），编辑器只是**把语言结构显形**，不是发明新架构。
> 信息架构（08-09 拍板）：车间 = **"数据处理开发"标签页**——"书房"从比喻变成字面：你走进一间房间，里面就是数据处理。

### 统一形象：逻辑是一个"活页面"，函数是它的书房

**可视化数据界面（数据页）** = 应用里的一个活页面：上面摆着真实内容（列表/卡片/图表/数值），直接操作——拖一个"分组控件"上去，内容当场变。起个名字（"报名统计"）→ 长进应用树，和页面/组件/条目并列，打开即用。**逻辑是应用的居民，不是后台的引擎；复用不是功能，是树的结构性质。**

**函数节点** = 数据页上的一个器官（格子）：逻辑复杂到可视化界面处理不了 → 在这页上开一个函数节点，把复杂逻辑扔进去。有门牌、有输入口、有输出口；打开 = 完整过程（工序带形态：进料 → 工序 → 出料）。

**客厅（简单、直观、直接摸）↔ 书房（复杂、正式、独处）——一个家，不是两个地方。**

### 升级 / 降级：一个动作

- 客厅内容"越来越复杂了" → **点一下** → 整组收进一个函数节点，客厅留下干净格子；函数里是完整过程（收进去的控件变成步骤清单，一样的形式，只是独立了）
- 函数里其实只是几个控件的事 → 点一下展开回客厅
- **升级/降级 = 换一种看法，不是换一个地方**。没有"去车间"的开关，只有"这一页想更简单还是更独立"的一念。

### 流水线（函数内部的工序形态）

- **进料口**：仓库内容 / 界面参数 / 外部来源 / 另一条流水线的成品（流水线可以吃流水线——复用自然长出来，用户不学"函数调用"）
- **工序带**：动词卡，拖来排序、点开配规则——挑出 / 排序 / 分组 / 汇总 / 加一列 / 合并 / 对每条做 / 分流（分拣口）/ 取外部 / 吃另一条流水线。规则是人的话，不是表达式
- **出料口**：回展厅（主要）/ 存档 / 触发另一条流水线
- **参数口**：留一个口（"按月份"），界面调用时从控件取值——同一份算法，多处使用
- **试机台**（心脏）：投样例 → 看产出 → 质检绿勾。保存几组样例当质检记录，每次改动后跑一遍。**正确性不靠读代码，靠看产出**（与测试数据集共用同一套样例，§6）
- **单步断点**（调试窗口）：试机台的深度形态——投样例看产出之上，逐工序看中间值、设断点停住。一个连续心智，不是新概念

### 桥：接数据 = 点名

界面上一个列表 → 属性面板"内容" → "来自数据页" → **点名一条** → 出料结构（字段）立刻出现在列配置；参数口自动变成界面控件（月份 → 下拉框）。**接数据只有一个动作：点名。**

### 三个入口（想法 → 流水线，路程是直的）

1. **就地升级**：行为卡里两步逻辑 → "想让它变成公共的？"一键升格
2. **界面反向**：列表摆好 → "给它一个来源" → 没有现成的 → "用一句话创建一条"（`把报名 → 按项目分组 → 统计每组人数` 直接产出骨架）
3. **需求即流水线**：先想要什么输出，再倒推工序

### 车间的健康

"这条流水线被 3 个界面点名"（点开看谁在用）/ "这两条差不多，合并成一条？" / "很久没人点名了"。流水线也在时间树上分叉：**试新算法 → 开分支 → 同一组质检样例喂给新旧两条 → 并排看差异 → 嫁接/扔。算法试验的恐惧也归零。**

## 9. 时间树：跨透镜的元层

> 用户认可："每一步操作都自动落在时间轴上"这个设计不错；"时间之树，这次设计非常不错"（树 = 升华版时间轴）

- **主干 = 现实**，当前工作的地方
- **分叉 = 平行世界**：回到昨天改一个决定 → 世界分叉。两个版本并存、并排对比、随时**嫁接**（把 B 版的某个页面拖进 A 版主干）、随时放弃
- **果实 = 发布**：每次发布在树上结一个果，随时可摘；**发布 = 一个按钮，B/C 用户全旅程的终点是"链接能用"**
- **播放成长纪录片**：快进看应用从一句话怎么长成现在的样子，每一帧都是可玩的版本
- **协作** = 多人在同一棵树上各自开枝
- **想法落地闭环**：想法 = 分支，手术 = 在分支里做，对比 = 并排，落地 = 嫁接，放弃 = 扔，发布 = 果实，倒带 = 撤销
- **信息架构（08-09 拍板）**：家族树 = **元层按钮**（不是标签页）——跨标签可用：撤销/版本/分支/发布与你在哪个标签无关。

所有操作自动落树：没有保存按钮，没有撤销弹窗——树的隐喻就是撤销、是版本、是灵感存档、是试错乐园。

## 10. 样式板块（定稿 · 08-09）

> 用户裁定（08-08）：前两轮设计"没有那种很妙的感觉"，搁置。08-09 会话重想定稿。
> 定位：**样式微调存在，但微调的"语言"是人话，不是数值**。用户的想法（"这个按钮再突出一点""我要红色""整体再专业一点"）直达落地。

### 已探索的两轮与教训（防止未来重蹈）

**第一轮 · 工具思维**（状态条 / 溯源链 / 一致助手 / 设计语言房间）——被否。
教训："设计的跟没设计一样"——还是"更好的属性面板"，给"调外观"这件事加功能，而 B/C 用户的障碍不在"怎么调"，在"不知道调什么、调完好不好看、每一步都是赌"。

**第二轮 · 含义反转**（用户不调外观，声明含义，外观自己长出来；身份 = 种子色 + 风格方向；角色 = 语义结构的镜子；试衣间）——方向认可（与语言"表达意图而非平台形状"同构），但**"没有妙的感觉"**。

**两轮之后看到的三个真相**：
1. **B/C 用户的三个障碍**——不知道调什么、调完好不好看、每一步都是赌。工具思维只解决了"调"的动作；含义反转解决了"调什么"，但"好不好看"（审美判断）和"赌"（怕弄坏）没解决。
2. **用户认可的设计全是"活的"隐喻**——内容**长**在界面上、应用的一生、时间**树**、一个**家**。样式要"妙"，也得是个活的东西。
3. **"比较感觉"这个动作两轮都没试过**——系统给 2-3 个**完整方案**，用户凭感觉选一个"更像我的"。**比较凭感觉，判断才需要专业**：用户不用判断"好不好看"，只需感受"哪个感觉对"。

### 定稿设计：两级——就地微调 + 设计语言场所

**① 就地微调（长在界面上，睡态即可用）**

| 机制 | 内容 |
|---|---|
| **词谱替代数字谱** | 每个外观维度是 3~7 个**词档**，不是数值滑杆：字号 = 正常/突出/标题级（不是 14px/18px/24px）；间距 = 紧凑/舒适/宽敞；圆角 = 方正/圆润/胶囊；层次 = 平面/轻浮起/浮起；明度 = 安静/标准/醒目。**值由系统按当前设计语言推导**——任何档位都长在"这身衣服"里，不会选出一个毁掉整体协调的裸值 |
| **精选色板替代色轮** | 颜色不出现 1600 万色轮（色轮是设计师的工具：操作简单，但**判断哪个色不毁设计**才是障碍）。出现系统按当前设计语言生成的 **8~10 个协调色块** + **语义身份**（主行动/警示/强调——点身份色自动变）。想自由 → 专家出口开色轮（与"代码是 DNA"同一逻辑） |
| **即时可逆替代"赌"** | 每一步换前/换后并排可见，一键返回。**让赌注归零**：代价是一步返回，不是毁掉整个设计 |

与第一轮工具思维的区别：不是给属性面板加功能，而是**把每个控件的语言从数值换成词、把判断换成精选、把赌换成可逆**——方向完全不同。

**② 设计语言场所（"样式开发"标签页）**

**样式 = 应用的人格**——每个应用有一个"人格"（冷静顾问 / 清爽助理 / 亲和伙伴…）：一个完整的审美系统（色彩×字体×间距×圆角×动效），不是参数而是"一个人"。**人格管整体，含义管重点，各管一段。**

| 机制 | 内容 |
|---|---|
| **换装 = 人格图谱为主** | 用户说"换个感觉" → 系统**读应用**（按应用是什么：记账/报名/打卡…）推荐 2-3 个气质方案，**并排陈列**，同一个应用三种气质 → 用户凭感觉选 → 全身换装。一个词换全身："妙"的瞬间 = 说了一句话，应用换了个人 |
| **指感觉为辅** | 库里没有的感觉 → 指着任何例子说"我要这种感觉" → 系统提炼成设计语言。限定在**应用/demo/网页**这类结构化界面（可完整提炼色彩字体间距动效）；图片只能提炼颜色（如实记录，不留隐患，拍板 #13） |
| **元素含义在气质内说话** | 给一个数字说"这是最重要的" → 它按当前气质的"强调方式"突出；说"这是警示" → 气质里自带的警示色。**不说的时候，语义身份让外观自动长对；想说的时候，词谱让人话直达** |
| **统一 = 系统默认行为** | 改一个按钮 → 系统问："应用里 8 个主按钮，一起变？"——用户不学"样式"这个词，就得到 Figma Styles 的全部好处。与结构透镜"这个卡片在 3 处重复，合并成一个？"同一已验证模式 |

**与 Figma 的对照**（08-09 用户裁定："学习它的优点，界面编辑器和设计编辑器不一样"）：
- **学**：直接操纵 + 即时反馈（与"应用即编辑器"同构）；Inspector 上下文化（= 语境面板）；**样式共享 = 一致性是系统的默认行为**（最被低估的优点）
- **不学**：色轮、数值输入、网格、像素精确、图层树——设计师的**判断工具**。B/C 用户的障碍不在"操作精确"，在"判断审美"。判断的活，系统扛

**语言契约**：词谱微调落到 .omni 还是合法输出（样式属性本来就是语言成员）；语义身份落到 token（域 5 已登记）；人格 = 设计语言的 token 集。编辑器只是给语言原有的表达各配了一个人话表面，不发明语言外概念。

**远期依赖**：样式体检（"这个按钮没人点 → 建议调弱"）依赖**运行数据回传语义**——语言目前没有，列为 post-冻结远期（deferrals 台账，带触发器）。

## 11. 设计契约（不留隐患的保证）

| 契约 | 内容 |
|---|---|
| **对象契约** | 产品只有五类对象：**应用 / 页面 / 组件 / 条目（内容） / 数据页（命名逻辑）**。所有视图都是投影。语言加新语义 → 对象多一个属性、面板多一节——**编辑器形态永远不会滞后于语言**。就地逻辑不是对象，是对象的属性 |
| **动作契约** | 每个编辑动作 = 一条意图；动作的历史 = .omni 文本。视觉与语义是同一个东西的两面——**不是"两个系统同步"，是"一个动作两种读法"** |
| **透镜契约** | 任何功能必须挂进某张透镜或某个对象属性；挂不进 = 设计缺陷，不许进产品。任何逻辑必须能归类为"就地"或"独立"之一 |
| **语言契约** | 编辑器不发明任何语言外概念。UI 上出现的每个词都是语言里的词（事件面板已语义化收敛的成果，延伸到全部 UI） |

**语言契约验证表**（设计概念 ↔ 语言语义，抽查）：

| 设计概念 | 语言对应 |
|---|---|
| 行为卡（就地逻辑） | action / computed |
| 数据页（命名逻辑） | fn / getter / @load |
| 工序带（动词卡） | 域 2 数组方法 |
| 内容（条目） | @store / 数据三态（域 9） |
| 收集 = 表单 | @form（域 8） |
| 状态预览开关 | 语义验证三态 / 值三态 |
| 幽灵元素（@if） | 条件渲染 |
| 一显多隐（@for） | 列表渲染 |
| 角色外观 / 状态外观 | token（域 5）/ 语义事件（域 3）视觉对应 |
| 语义身份 / 人格 | token（域 5） |
| 呼吸三态（睡/醒/调试） | 视图层 / 逻辑接线层 / 运行时 |
| 测试数据集（活体模特） | 值三态（空/加载/错误/数据） |
| 换页（发射端/接收端） | 域 11 导航（@route / navigate / back，§16） |

## 12. 与探路轨的对齐

- 官方范围：**设计画布面（布局界面效率 / WYSIWYG / 设计系统）+ CodeFlow UX（节点形态/交互/布局）**。本设计将其扩展为四透镜 + 车间 + 时间树 + 四标签页；**@form/@load 可视化范式现在锁定 = 冻结前零迁移成本窗口**（域 8/9 登记中、语料零使用、编辑器未接——真正的绿地）。
- 三条硬约束（.omni 往返兼容 / 语法零变更 / 四链同步）：本设计全程遵守——所有表面都产出 .omni 文本，视觉与语义同源（动作契约）。
- **投入约束**：编译器主线优先，探索用每周剩余精力（roadmap 决策 13）——本设计以"设计文档 + Storybook 原型"形态推进，不抢占编译器主线。
- **先例**：ADR-075"语义化即切换，不留旧残留"——可视化操作产出的也应该是语义，不保留"视觉残留"（编辑器不得发明与语言语义不对应的中间形态）。
- 历史关联：docs/design/visual-editor-design.md v1.5（WYSIWYG 布局画布 + 事件→连线跳转）是 v5 决策的败方（败因 = 积木输入速度 vs 开发者打字）；**目标用户换成 B/C 后败因前提失效**，其交互细节仍是本设计的合法先例，原型阶段先消化再动工。
- 远期：样式体检 / 试衣间运行数据依赖 → post-冻结，先设计后落地。

## 15. 数据绑定与渲染深化（定稿 · 08-10）

> 08-10 设计会话。问题起点：**"接数据"是界面与数据处理之间的连线，而界面的数据来源很多（store / 组件 signal / 变量 / 数据页 / @load / @form…）——来源谱系 × 绑定形态的笛卡尔积很复杂。正因为复杂，可视化编辑器才有价值；这块的体验要极佳。**
> 起点裁定（用户）：数据绑定 = 数据绑定到界面上、界面把数据显示出来；既然可视化编辑，就用**连线**把数据流接到界面上；接线发生在"醒"（睡 = 专门设计界面样式，不接）。

### 15.1 总纲：接数据 = 连线；睡/醒分工

- **醒 = 接线的时刻**：睡态界面干净、专心样式；醒来，数据流变成可见的线，把数据处理和界面相连，也把界面元素之间相连（输入框的"值" → 标题的"文本"，一条线的事）。
- **渲染形态的"壳"是睡态设计的，数据是醒态接的**：设计的是"两种情形下的样子"（有内容的正身 + 空/假时的样子），不是透明度。
- **临时调试模式（睡态工具）**：设计条件渲染/列表渲染 = 拨数据，不是画壳——睡态在数据节点面板上改 store/signal 的值（或换数据集），界面当场演，直接在演出的样子上调样式。

### 15.2 数据源 = 节点（常驻 · 可唤出）

- **来源是节点**：store / signal / 变量 / 数据页等数据源 = 节点编辑式的**源节点**（store = 一本账本、数据页 = 一张工作台、signal = 一盏小灯、变量 = 一张便签）。可摆放，**默认自动布局**（初始整齐排在画布一角"数据区"，用户可拖到自己顺手的位置）。
- **常驻但可唤出**：平时隐去，由**底栏"数据节点"开关**点一下显示、再点隐藏（Figma 式底栏切换）。数据面板 = **全局的**——管所有 store/signal 的值调试，不跟选中元素走。
- **数据面板与内容标签页的关系**：数据面板（全局，管数据值与调试）↔ 内容标签页（选中元素的接口）是两个世界，靠**线**连接。点内容标签时数据面板自动浮现，方便看线头。

### 15.3 线的语言（六接口 · 同一种线）

- **元素也长数据端口**：输入框有"值"出口、标题有"文本"入口——元素既是界面也是数据节点，睡态端口隐去。
- **接口六种，同一种线**：文本内容（`{x}`）/ 输入值（`bind:value` 双向）/ 列表内容（`@for`）/ 显示条件（`@if`）/ 属性值（图片地址/禁用/跳转）/ 事件参数——都是元素上的一个小圆点，拉线即绑定。**复杂度用一套机制吃下**：用户学一次拉线，会绑一切。
- **线的语言**：一种中性色线（不与应用设计色打架）+ **方向箭头**（单向 `→` 显示、双向 `↔` 输入）+ **接口形状**（文本圆点、列表双竖线、条件菱形、属性方块…——接口形状长在元素上，不用额外学）。醒态线有微弱的流动动画（数据真的在流），睡态静止。
- 接条件 = 点亮幽灵的前提；接列表 = 告诉"一显多隐"数据是谁——与 §4 幽灵元素/一显多隐咬合。

### 15.4 部分唤醒（线随醒处）

- **接线发生在醒；醒可以是一小片**：选中某组件点醒 → 只有醒的区域连线显示，睡着的部分没有线、照样专心样式——**"线乱/蜘蛛网"被结构性化解**：线本质上属于醒的区域，你在接线才醒，醒了才见线。
- **接完 = 线收起**：日常（睡态和醒态平时）线不存在，接口上只留**来源印记**（小徽章："来自 报名记录"）。**关心时线才回来**：悬停/选中元素 → 它吃的那几条线亮起；选中源节点 → 它喂给谁亮起。大簇自动打包（×12，点开散开）。
- **线是物理动作**：拖线那一刻是物理的（从源节点拉到接口，接完松手）。

### 15.5 浮动语境面板（标签页制 · 非固定侧栏）

- **浮动语境面板**：选中元素 → 面板**浮在元素旁边**（替代固定右侧栏；元素一动面板跟着走；旁边放不下弹向另一侧/上方；可手动拖走）。什么都不选 → 面板收成小浮标（应用的面板）。
- **标签页制**：`[ 样子 ] [ 内容 ] [ 行为 ] [ 结构 ]`——每个标签 = 一类设计动作，标签页给足内部空间，绑定类做成可视化界面而非下拉。
- **内容标签页 = 选中元素的接口**：只做这个元素的接口与连线——睡态看已接的线（来源印记），醒态接/断；不承载"改数据"（改数据在全局数据面板）。

### 15.6 样式复用 = 衣柜穿衣（绑定 Token/Class 的可视化）

> 用户问题："样式设计时假如想要复用一些样式怎么办？""怎么给组件或元素绑定 Token 或 Class？"——**样式复用此前没有设计过**。解法 = 不设计"绑定"，设计"穿"。

- **界面不出现 Token/Class 这两个词**：Token/Class 是系统在背后的实现（语言契约：词谱微调落到 token、语义身份落到 token，§10 已保证）；用户语言是"样子"。专家出口 = Design 标签页（Token/Class 真身），日常不出现。
- **衣柜视图（样子标签页内）**：绑定 = **可视化穿衣**——
  - 系统推荐（按元素类型推荐 2-3 个样子卡）+ 当前穿着的打勾 + 全部样子（可搜索）
  - 样子卡 = **实时小样渲染**（一个按钮卡就渲染一个小按钮，用那个样子的真样式）——**不是下拉选名字，是看小样挑衣服**
  - 点卡 = 穿上
- **存样子**：元素上就地微调（词谱/色板）→ 卡上显示"未保存的改动" + 气泡"存成一个新样子？"——**改着改着就存了**（与组件长出来、§10 同一机制）。
- **一起变**："应用里 8 个主按钮，一起变？"做在**样子的卡**上：卡上"8 处"徽章 → 点开 = 位置列表；改卡 = 处处变。用户改的是样子，不是 8 个元素（= Figma Styles 的好处，用户不学"样式"这个词）。
- **默认穿衣**：第一个文字自动穿上"标题"样子、按钮穿上"主按钮"——系统给方案、用户做选择（已验证模式）。

### 15.7 底栏 = 睡态工具的家（用得着才长）

- **底栏两件套起步**：`[ 组件库 ] [ 数据节点 ]`——组件库（开发第一件事：拖东西）、数据节点开关（拖完喂数据）。设备框等后续需要时再加，**一步一个设计**。
- **其他睡态工具不占底栏**：换数据集住进数据面板操控台；幽灵态切换/样子管理住语境面板——**工具进底栏必须有一个明确的"全局性、与选不选中无关"的睡态场景**，否则住语境面板/操控台。

### 15.8 语言契约检查

| 设计概念 | 语言对应 |
|---|---|
| 源节点（store/signal/变量/数据页） | store / signal / computed / let / fn / getter / @load |
| 文本接口 | `{expr}` 插值 |
| 值接口（双向） | `bind:value` |
| 列表接口 | `@for` / `@empty` |
| 条件接口 | `@if` / `@elif` / `@else` |
| 属性接口 | 元素属性 |
| 事件参数接口 | 事件数据 schema（域 3 语义事件） |
| 临时调试模式 | 值三态（静态文本 / {expr} / 裸布尔，ADR-068）+ 测试数据集（§6） |
| 衣柜穿衣 | token（域 5）/ class（style 块） |
| 部分唤醒 | 逻辑接线层（睡 = 视图层、醒 = 接线层、调试 = 运行时，§3） |
| 换页（发射端/接收端） | navigate / @route 路径参数注入（域 11） |
| 页级"这一条"入口 | 路径参数注入 prop |

## 16. 页与页之间的数据交接：发射端 / 接收端（定稿 · 08-11）

> 08-11 设计会话（G2）。问题起点：**列表 → 详情页是应用最常用的模式（"点这一条看它的详情"），但导航（§7 结构透镜）与数据（§15 内容透镜）的接缝没有设计——"去那页"和"带这一条"之间断了**。探索结论：页间**不画线**（连线只属于页内同空间，§15）；换页 = 无线电模型——**发射端配置"点它会怎样"，接收端声明"这页收什么"，两端对频自动连通**。导航 = 配置，不是画线。

### 16.1 换页两档（遵语法）

- **整页换**（整个页面走掉）= 本节发射端/接收端模型——"点它去另一页"是一个可配置的动作
- **局部换**（页内一小块切换/显隐）= @if 渲染（幽灵元素，§4）——**不进换页设计**；与语言边界一致（"@if 互斥切页是合法语法"，Tab 与路由边界，docs/omniview/18）
- 语言对照：整页换 → `@route` / `navigate` / `back`（域 11）；局部换 → 条件渲染。**换页设计不发明语法外概念**

### 16.2 发射端（发送方）

- **位置**：选中元素 → 浮动语境面板（§15.5）新增 **"设计路由"标签页**——与 样子/内容/行为/结构 并列
- **内容**：配置"点它会怎样"——**去哪一页**（选目标页 = 调频道）+ **带什么数据**（发送数据）
- 例子：选中列表条目 → 设计路由标签 → "点它去 [活动详情页]，发送 [这一条·活动]"
- 纯导航（不带数据）："点这个'我的'按钮去我的页"——同一标签页，只选目标页，不发送数据

### 16.3 接收端（接收方）

- **位置**：设计窗口切到目标页时，**同一个浮动面板**的"设计路由"标签页内容变为接收端——不发明新面板，一个面板两种面孔
- **内容**：声明"这页接收什么"——接收的数据类型（如 活动·这一条）
- 接收端声明后，页内自动获得**"这一条"入口**：源节点面板多一个"这一条"（页级源节点）——标题、统计、表单预填等页内绑定照旧从它拉线/点名，**一次接线全页受益**
- 语法背后：接收端 = `@route "/activities/:id"` 路径参数注入 + 页内按 id 取这一条——**URL 即数据源，深链/刷新/分享免费成立**；开发时没有"从列表来"也能直接演这页（活体模特喂"这一条"，§16.5）

### 16.4 对频（连通判定）

- 发射端选目标页 = 调频道；系统按 **目标页一致 + 数据类型一致** 自动判定连通
- **两端面板互显对方**：发射端显示"已连接 → 活动详情页"；接收端显示"来自 ← 活动列表"
- 配不上（发的是 报名，这页收的是 活动）→ **面板内提示**（反馈长在面板里，不弹窗打断）
- 一个接收端多个发射端（列表页能进、首页也能进）→ 接收端面板显示"**N 处可进来**"，点开看位置列表（与"8 处徽章"、来源印记同一机制）

### 16.5 调试 / 测试

- 接收端的"这一条"就是活体模特：调试窗口拨"下一条"，详情页当场演（与 §6 测试数据集、§3 临时调试模式咬合）

### 16.6 语言契约检查

| 设计概念 | 语言对应 |
|---|---|
| 发射端（点它去哪 + 带什么） | `navigate(path, { params })`（域 11） |
| 接收端（这页收什么） | `@route` 路径参数注入 + 页内按 id 取（域 11） |
| 整页换 / 局部换 分界 | @route/navigate ↔ @if 条件渲染 |
| 页级"这一条"入口 | 路径参数注入 prop |

## 17. 阶段实施 v1：统一画布 + 睡/醒（定稿 · 08-11）

> 08-11 设计会话（grill-with-docs）。用户裁定："目前先实现一个阶段——把 designcanvas 和 codeflowcanvas 打通变为一个，然后使用'睡 / 醒'的设计"。本阶段是探路轨到实施的**第一个落地阶段**（设计 → 实施的桥），范围 = 画布打通 + 睡/醒 + 语境面板（替代右栏）+ 底栏 + 源节点。里程碑 M1→M2→M3 交付，每里程碑单独验收。

### 17.1 范围一句话

设计画布与 CodeFlow 逻辑画布从"互斥两块"变为**一块画布、两种呼吸**；事件/数据绑定由弹出的语境面板完成；睡态工具住进底栏。

### 17.2 画布形态（打通）

- 设计层 DOM 渲染（WASM 元素树）**不动**；醒态在之上叠加 ReactFlow 逻辑层（fn 节点 + 源节点 + 手柄 + 线）
- **视口同步**：zoom/pan 单一真相（现有 useCanvasStore 驱动 ReactFlow viewport），两引擎并存但用户只见一块画布
- **技术事实**：设计元素是 CSS 流式布局、ReactFlow 节点是自由坐标——元素整体迁入 ReactFlow 会砸流式布局；故叠加层 + 手柄按元素实际位置**长在元素上**（= §15.3"端口长在元素上"，不是妥协）
- 删除：双击进出逻辑画布模式、TopLayer 缩放隐藏互斥、DesignPreviewNode 只读快照伪节点

### 17.3 睡 / 醒 规则

- **呼吸点** = 设计窗口角落小脉搏：点 = 整页醒（逻辑层浮现），再点 = 睡（干净画布）
- **[内容] 标签自动醒**（意图驱动）：睡态选中元素 → 面板弹出 → 点 [内容] → 自动醒；todo：局部唤醒（#29）落地时细化为只醒选中元素
- **取消选中 → 睡回**：端口/线收起，接口留**来源印记**；悬停/选中 → 线亮回
- **Shift 多选 = 醒区**（线随醒处，#29 的落地点）：新元素局部醒 + 弹副面板；**最多 2 个面板**（主 + 副）
- 睡/醒 = 数据流动开关，正交于样式编辑（#17）：醒着也能改样式
- 源节点只在醒态可见（本阶段）；**改值调试**（临时调试模式，#34）落在醒态

### 17.7 绑定与落盘（语法零变更）

- **事件** = 行为卡（最小动词集 ~10 个起步，G3 后置扩充）→ 落盘 `@onClick` + **自动生成 fn**（用户不写不看，面板改 fn 跟着改）
- **数据五类槽**（文本 `{expr}` / 输入 `bind:value` / 列表 `@for` / 条件 `@if` / 属性）→ [内容] 标签点名绑定
- **元素间连线 = 自动中转 signal**（语言事实：`{ref.value}` 是快照非响应式、bind:value 只绑 signal——**语言无元素直接引用**，唯一响应式路是 signal 中转）：
  - 命名 `<源元素>_<源槽位语义>`（`nameInput_value` / `checkbox_checked`）；无 @ref 时源名 = 类型+序号（`input_2`）；生成后可改名
  - **同槽复用**：一个元素的"值"喂 N 个目标 = **同一个 signal**（signal 本性可复用），不重名、不建多条
  - 数据区**独立分组"自动连线"**，与用户 signal 分排；断线且无引用 → 回收
  - 线源限三类：值型控件（input/textarea/select/slider）、源节点（store/signal）、fn 出口；显示元素当源后置
- **绑定两路并存**：画布手柄拖线（ReactFlow 节点式拉线）+ 面板点名（点槽 → 选来源清单）
