How It Works: @themes Syntax

Design blocks declare themes via @themes directive. Per-token per-theme values compile to layer CSS.

Source 

                        @themes light, dark, sepia, highContrast; @default-theme light; token primary: color = "#6366f1" dark "#a5b4fc" sepia "#8B4513" highContrast "#ffff00"; token surface: color = "#ffffff" dark "#111827" sepia "#F5E6C8" highContrast "#000000"; token textPrimary: color = "#111827" dark "#f9fafb" sepia "#3E2723" highContrast "#ffffff";

CSS 

                        :root &#123; --primary: #6366f1; --surface: #ffffff; --textPrimary: #111827; &#125; [data-theme="dark"] &#123; --primary: #a5b4fc; --surface: #111827; &#125; [data-theme="sepia"] &#123; --primary: #8B4513; --surface: #F5E6C8; &#125; [data-theme="highContrast"] &#123; --primary: #ffff00; --surface: #0; &#125; @media (prefers-color-scheme: dark) &#123; :root:not([data-theme]) &#123; --primary: #a5b4fc; &#125; &#125;

CSS Custom Properties (CSS Variables)

演示编译器对 --* 声明、 var() 引用、内联静态/动态 CSS 变量的完整支持

① Style 块声明 --* + var() 引用

Style 块内部声明 --primary 、 --bg 等自定义属性， 然后用 var() 引用。这是编译器中 parse_css_property_name() 解析 -- 前缀的常规路径。

var(--primary)
var(--primary-alt)
background: var(--surface)
border: var(--border-color)

② 内联样式静态 CSS 变量

在 style: &#123; --name: "value" &#125; 中直接写 -- 属性。 编译器代码生成将 -- 属性用 el.style.setProperty("--name", value) 输出，而非普通的 el.style.prop = value 。

--box-bg: "#e0e7ff"
--box-radius: "16px"
--box-radius: "50%"

③ 内联样式动态 CSS 变量（信号 → setProperty）

传递 信号引用 给 --* 属性。编译器自动生成 __omni_effect(() => el.style.setProperty("--name", signal.value)) 。 这是新增的 $signal JSON 标记代码路径。

💡 语法状态速查

  • 类型化插槽：三目标均可编译，类型约束目前是 声明侧文档 ——React 生成 header?: string ，Flutter 警告并退化为 Widget? ，OmniView 不消费类型
  • ：语法可解析并进入 IR，但 尚无代码生成目标消费 该提示（Flutter ListView.builder 提示待实现；OmniView 无效果），此处不演示无效果语法
  • 泛型：类型实参（Array、Map 形式）可用；泛型声明 fn foo / component Bar 的类型参数尚未支持（完整说明见文件头注释）

Phase 1: Compile-time Constant References

Const values from other files can be used as token values. The compiler resolves them at build time with zero runtime cost.

shadow var

These CSS vars are baked into :root at compile time. No JS needed.

Phase 2: Runtime Signal References

Store signals can be referenced in token values. The compiler generates a bridge that updates CSS when signals change.

How It Works

Parser

Expression-first detection for token values.

Semantic

Reference resolution and type validation.

IR Lowering

Static tokens go to CSS, dynamic to JS bridge.

Codegen

CSS for static tokens, JS effect for dynamic.

Key Rules

  • Dynamic tokens cannot have theme overrides.
  • Priority: setProperty then data-theme then :root.
  • Type must match: String for Color, int for Duration.
